# 灵犀问数优化完善计划

日期：2026-10-23。范围：灵犀问数及其必要的底座接口，不扩展另外四个项目。状态：**计划已编制，以下新增任务均未执行**。

## 一、目标与现状

目标是把已经完成实现和隔离验证的一期，推进到有真实业务口径、真实身份与模型、稳定数据同步、质量证据及运维交接的小范围生产服务，再逐步扩展复杂问数能力。

最新基线以20号交付记录和仓库 `docs/enterprise-current-status.md` 为准：原清单49项中36项实现/隔离通过，13项待企业输入或外部验收；正式后端75项、前端30项、评测器3项分别通过，历史兼容406项单独统计。真实StarRocks/PG已经验证；身份、生成、Embedding目前主要是协议桩验证。不能据此承诺真实模型准确率、生产并发或企业已上线。

已完成的异步任务、幂等、租约、撤权、数据库取消、区域隔离、不可变快照及发布回滚保留，在后续变更中回归验证，不重复立项重做。

## 二、固定边界

- 正式开发、CI、预生产和生产均使用StarRocks 3.5.21；PG17负责控制面与schema向量。历史DuckDB兼容链路不进入生产。
- 问数通过内网底座调用 `local-chat`，基线为 `Qwen/Qwen3.5-27B-FP8`；`embedding-default` 为BGE-M3、1024维。实际不可变权重revision接通后登记；本计划不新增云端回退。
- 沿用FastAPI、React/TypeScript/ECharts、OIDC/PKCE及现有异步API。源数据走既定ODS/DWD/DIM/DWS/ADS治理路径，持续同步采用Flink CDC及StarRocks connector，批处理和对账采用Airflow。
- 先开放少量已批准指标和授权范围。500表是目录规模，不意味着一次性开放500张原始表，也不能单凭表数推算性能。
- 微调、独立语义复核模型、多轮追问列为后续有条件建设项，不作为一期上线的默认前提。尚未批准的复杂口径继续澄清，不强行生成SQL。

### 质量门槛如何制定

在正式盲测前由Owner批准每档的正确回答率、错误回答上限、澄清/拒答覆盖率以及延迟预算，并写入版本化验收表，不能看成绩后修改门槛。安全负例要求测试集中零越权、零写入、零跨用户结果泄漏；这只是本次验收集的结论，不是对所有未来输入的绝对保证。首批批准模板须逐项独立数值对账通过。

题集建议最终形成100条单表、100条常规关联、100条复杂问法及50条行为/安全用例；复杂部分包含应澄清的未开放需求，不能都按成功生成SQL评分。先用约60条开发诊断集查问题，再冻结独立350条验收集；开发集不计入盲测，同义改写及相同查询模板应分组去重。350条是工作目标，不是现有资产或统计精度保证；业务复核不足时先缩小上线范围。

## 六、执行顺序与阶段交付

1. **准备阶段**：建立首批指标签收表、外部输入清单、分档评测规范。账号、Secret通过企业配置渠道提供，不在文档或聊天粘贴。
2. **先接通**：P0-01 → P0-02/03 → P0-04。SSO与模型可交错推进，但单人工作量不能按多团队并行压缩。
3. **再证明**：P0-05/06 → P0-07。先完成预生产证据，再受控灰度；性能指标未验收不宣传容量，质量不达标缩小范围。
4. **再优化**：优先P1-01，其次P1-03和真实评测暴露的问题；其余P1按瓶颈推进。
5. **最后增强**：评估P2-01/02收益；微调保持条件立项。增加模型调用不能替代指标治理、数据对账和权限校验。

建议先单独批准P0工作包，不把全部优化作为首次上线前提。P0与P1若全部顺序完成，约35–52人日，建议9–14个日历周；P2另排。所有区间都是依据当前范围的工程估算，依赖齐备后按实际源系统、环境和验收范围重新排期。

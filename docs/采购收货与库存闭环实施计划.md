# 采购收货与库存闭环实施计划

目标：在原有500表中增加可追溯的模拟采购创建、分批收货及正向库存流水，和上阶段出库共享库存快照重算能力。

1. 扩展严格批次协议：purchase.created 与 purchase.received；采购行数量和金额明确，收货按行、仓库及数量提交。
2. 原子写入采购头明细、收货及入库流水；按所有仓库累计防超收，校验主数据、日期、业务ID。
3. 共享库存重算，增加全量采购数量及日期门禁；对新增事件建立来源逐笔对账。
4. 测试部分收货、跨仓累计超收、错误整批回滚、历史快照修正和权限。
5. 在真实500表模拟实例演练入库、超收隔离、发布、重复接入及回滚重放，完成问数与备份恢复验收。

范围：自建模拟数据，无真实企业接口。仅数量收货，不实现应付、供应商付款、质检拒收、退供或序列号入库。历史种子采购收货和库存流水原先独立生成，不宣称历史采购已逐笔入库对账。区域账号仅查看本区收货及库存，采购头明细缺少所属地区，继续拒绝向区域账号开放，以免泄露其他仓库订购量。

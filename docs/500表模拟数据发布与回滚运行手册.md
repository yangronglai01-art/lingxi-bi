## 数据发布流程

```powershell
cd D:\projects\lingxi
# 查看当前版本和通过校验的版本
.\.venv\Scripts\python.exe scripts/manage_releases.py status
# 构建下一批候选示例；不会改变当前版本。保存命令返回的generation
.\.venv\Scripts\python.exe scripts/manage_releases.py stage --orders 3400
.\.venv\Scripts\python.exe scripts/manage_releases.py validate --generation '候选generation'
.\.venv\Scripts\python.exe scripts/manage_releases.py activate --generation '候选generation' --expected-current 'petkit-v1.3-587f2c8f8d'
```

所有操作由有服务器文件权限的本机运维终端执行，不向业务员工开放发布API。已初始化的业务实例禁止旧build_petkit500.py直接发布，防止绕过校验。候选校验有独立锁，不长期占用任务提交/领取锁；实际切换短暂互斥。

发布门禁包含：

- 500张物理表与元数据目录、列顺序和类型一致，每表数据量与构建摘要一致。
- 40张核心表的明确单键或复合粒度非空且不重复，511条登记关系无悬空外键。
- 订单行/订单/支付金额一致，退款金额及日期合理，订单行数量与设备桥接一致，库存快照可由流水重算。
- 32个批准SQL经原始记录独立Python计算核对；观察窗及30天百分数契约通过。
- 当前启用员工的地区仍存在；本机BGE索引能够装载并检索，当前506条1024维向量复用持久缓存。

校验记录只证明上述检查，不是所有业务约束的形式证明。校验时不调用LLM；它不代表32道自然语言任意生成的模型准确率。

校验凭证保存数据库、目录、摘要的SHA-256，以及17个指定关键代码文件的哈希和模型配置指纹。发布时再次核对；候选数据、代码或模型变化后要重新校验。模型指纹沿用本地文件大小/修改时间及配置，不宣称逐字节哈希2GB权重。代码部署后还应重启应用进程，不能依赖旧进程热加载。

每次校验保存在data/petkit500/validation_runs，最新凭证在releases/{generation}.json。失败候选保持rejected，当前指针不变。快照目录按约定不可手工修改，历史版本保留用于追溯和回滚。

## 与业务任务的关系

任务提交、任务领取、员工地区变更与发布共用实例锁。存在状态running的任务时拒绝发布，等待完成或租约恢复后再执行。发布完成后旧版本queued任务变为superseded，提示重新提交；不会使用新数据静默执行旧任务。

幂等键按员工、授权版本和数据版本共同作用；数据变更后相同键可创建对应新版本的新任务。过去completed结果继续作为历史结果保存，generation表示其实际数据版本。

## 回滚

已验证的原基线：`petkit-v1.3-2dc93c9e1c`。

```powershell
.\.venv\Scripts\python.exe scripts/manage_releases.py rollback --generation 'petkit-v1.3-2dc93c9e1c' --expected-current 'petkit-v1.3-587f2c8f8d'
```

回滚走同样的文件、代码、模型和权限门禁。当前代码或模型配置改变后，先重新validate回滚目标。若旧版本目录不存在，不可仅靠历史审计记录回滚。回滚也会使原版本的排队任务失效，员工需要重新提交。

本轮最终保留在3200订单版本，上述命令是后续操作说明，不需要为了查看应用再执行一次回滚。

## 发布中断恢复

发布先记录prepared意图，再原子替换current.json，随后在SQLite事务中更新旧任务和发布审计，最后写committed记录。文件系统和SQLite并非一个原子事务，因此通过可协调恢复协议补齐中间状态。

- 尚未替换指针：下次协调将意图标记aborted，继续使用原数据。
- 指针已替换：校验凭证后补齐任务失效及审计，使用唯一发布ID避免重复提交审计。
- 指针与日志冲突或凭证无效：拒绝继续领取任务，保留现场供运维检查，不猜测目标版本。

任务提交/领取会触发协调；prepared状态下/ready返回503。手工检查可执行：

```powershell
.\.venv\Scripts\python.exe scripts/manage_releases.py reconcile
```

故障注入测试覆盖指针切换前中断、控制事务提交后但完成文件未写入、重复协调、执行中任务阻断、坏凭证保护和回滚。仍不代表对断电磁盘损坏、网络文件系统或分布式协调的完整验证。

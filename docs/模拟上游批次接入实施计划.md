# 模拟上游批次接入实施计划

日期：2026-10-17。

1. 定义严格JSON批次协议，接收退款、首次激活、工单创建事件；使用本地模拟网关文件，不连接企业真实接口。
2. 批次及事件ID幂等，冲突ID拒绝。区分“已收到”与“已在当前快照中应用”，避免未发布候选、回滚或分支导致漏数据。
3. 从当前不可变快照复制候选，在单个DuckDB事务内应用整个批次；字段、主键、外键、金额、日期和业务规则不合法则全批失败，原始批次隔离保存，当前业务数据不变。
4. 保存原始批次摘要和快照级事件血缘。候选继续通过既有500表质量和32题独立结果门禁；发布使用父版本CAS保护，不覆盖别人已发布的新数据。
5. 演练有效批次接入、重复投递、冲突及坏数据隔离、发布后指标变化、回滚后同批次重放，验证不重复记账也不漏记。
6. 更新备份与恢复，保留接入血缘和来源证据；完成真实员工任务、全量回归及运行手册。

范围：固定观察截止日内的历史事件补录，支持三种新增事件。不是通用CDC、订单全生命周期同步或已经对接小佩真实系统。

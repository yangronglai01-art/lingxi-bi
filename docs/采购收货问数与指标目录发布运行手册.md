# 采购收货问数与指标目录发布运行手册

## 直接使用

启动模拟应用：`python scripts/start_simulated.py`。默认使用真实模型，`--mode demo` 使用批准模板。参考问题列表按账号权限过滤。

新增指标为“采购收货数量”，按收货日期统计 `fact_receipt.quantity` 的合计，以件为单位，按仓库分组。新增五个批准问题：全期、2026年3月、6月、8月、9月的各仓库采购收货数量。例如输入 `2026年9月各仓库采购收货数量`。

这不是收货单数、采购订购量、金额或期末库存。包含历史种子收货与本轮新增来源收货，不意味着历史种子已经逐笔补齐入库流水。

## 账号和权限

新增模拟账号 `regional_supply`，部门区域仓储、角色 `supply`、地区 R1。现有四个账号的凭据保持原样。凭据仍在本机忽略提交的 `data/petkit500/simulated_credentials.json`。

仓储角色只能使用批准的供应链及共享维度数据，区域视图约束实际读取的收货、库存和出入库记录。采购头与采购行缺少地区归属，暂不对区域账号开放。销售、售后、基础查看账号不能使用收货数量指标；仓储账号不能查询销售指标。任务历史按账号和授权版本隔离。

## SQL与单位契约

收货数量当前批准的形态为 `fact_receipt` 与 `dim_warehouse` 直接关联后 `SUM(quantity)`；不使用CTE、额外事实关联、COUNT、SUM(DISTINCT quantity)或数量乘金额等公式。SQL门禁检查该有限形态，输出列别名必须为 `received_units`，结果须为非负整数件数。此检查并非任意SQL语义等价证明，日期与其他过滤仍需业务评测验证。

## 只更新指标目录

指标定义代码发生变更后，可单独生成目录候选：

```powershell
.\.venv\Scripts\python.exe scripts/manage_releases.py stage-catalog
.\.venv\Scripts\python.exe scripts/manage_releases.py validate --generation <候选版本>
.\.venv\Scripts\python.exe scripts/manage_releases.py activate --generation <候选版本> --expected-current <父版本>
```

当前目录已更新，重复stage-catalog会提示无需生成候选。生成候选不会立即影响当前业务；每个候选保留父版本、数据库摘要、表结构摘要、来源血缘及持久审计证据。业务数据库文件字节必须与父版本相同，仅指标目录、版本与验证说明允许改变。新目录必须与当前指标代码一致。

后续接入业务事件时会移除继承的目录升级标记，继续使用业务接入的原子事务、来源对账和发布门禁。备份包含当前目录标记及控制库审计，恢复验证不依赖已经不在副本中的父版本文件夹。

历史目录按其声明且受当前代码支持的指标校验：此前目录32条，新目录37条。明确的历史回滚使用原有 `rollback --generation <历史版本> --expected-current <当前版本>` 入口；回滚后当前可用参考问题跟随历史目录变化。基础指标缺失、未知或重复指标会拒绝发布。已生成候选仍需基于自己的父版本发布，避免覆盖他人更新。

## 验收与证据

- 500张物理表、3,202笔销售订单、205,397行，没有为了上线新指标新增采购、收货或其他业务事件。
- 316项回归测试通过，业务独立口径校验37条；一条既有测试依赖弃用提示。
- 两条真实模型问题：全局9月收货20件，区域仓储10件，由Python直接遍历收货事实按月份及可信地区筛选独立核算。该小样本验收不代表任意问题准确率。
- 销售、售后、基础查看角色查收货数量被拒绝；仓储角色查销售指标被拒绝，其他账号任务不可读取。
- 来源血缘25个事件保持不变，目录候选业务库SHA256与父版本相同。

脚本：`scripts/accept_receipt_model.py` 会触发两条真实模型问数及权限拒绝检查；`scripts/accept_restored_receipts.py` 使用恢复副本上的批准模板，不调用付费模型。

原始证据：`reports/petkit500_receipt_metric_publication.json`、`reports/petkit500_receipt_model_acceptance.json`、`reports/petkit500_restored_receipts_acceptance.json`；汇总：`reports/petkit500_receipt_metric_rollout_summary.json`。

全部使用自建模拟数据，尚未接入小佩真实系统；仍是单机实例，没有完成长期负载或多机高可用验收。

# 自动工作进程守护运行手册

当前本地模拟实例默认启用工作进程自动守护，未接真实企业系统；本轮没有增加业务数据或付费模型调用。

## 启动和停止

```powershell
.\.venv\Scripts\python.exe scripts/start_simulated.py
```

默认llm模式；使用 `--mode demo` 选择批准模板。Ctrl+C停止本启动器及其拥有的API、UI和工作进程。每个实例目录只允许一个启动器，重复启动会在创建子进程前拒绝；不同实例目录仍需使用不同端口。

工作进程退出后，默认依次退避0.5、1、2秒，累计最多重启3次。预算按本次启动累计，健康运行不会自动清零；操作者明确重新启动整个启动器后才重置。第四次工作进程死亡会耗尽预算，关闭本启动器拥有的所有进程，保留失败审计，命令行启动器以错误结束。

可用参数：`--max-worker-restarts 3`（范围0至10）、`--restart-backoff 0.5`（首轮退避0.1至10秒，之后指数增加、每轮不超过10秒）。`--no-supervise`只供人工故障验收使用，会关闭自动工作进程守护。上一轮 `scripts/accept_durable_stability.py` 已明确选择人工模式，继续保留原来的人工恢复语义。

API或UI进程退出时停止其余自有进程，交由操作者排查；当前不自动拉起API或UI。正常退出期间不会触发新的工作进程重启。

## 健康与审计

`GET /ready` 在守护模式下同时检查当前启动会话、实际工作进程PID、工作心跳及守护状态。处于backoff、starting、unhealthy或failed时不报告就绪，重启过程中可观察到503，工作进程更新本次会话心跳后恢复200。每个会话使用独立随机标识，该标识不作为认证凭据。

守护状态位于控制库runtime的supervisor记录；开始、调度重启、新进程启动、就绪、失败和停止事件进入持久审计。全局分析账号可通过既有运维概况查看审计，其他员工权限保持原样。

Windows虚拟环境的重定向启动器PID可能与实际Python进程不同。启动器现在直接启动基础解释器，并保留虚拟环境前缀与依赖；回归测试实际验证Popen PID等于子进程PID，且FastAPI来自原虚拟环境，避免错误绑定心跳或只跟踪重定向进程。

## 任务恢复边界

自动重启的是进程，不是原任务。原运行任务保留60秒租约，租约自然到期后标记interrupted，不自动重放可能已产生费用的模型调用。原幂等键仍返回原中断任务；新幂等键重新提交后正常执行。工作进程恢复后可以继续处理其他排队任务，API和UI在允许的工作进程重启期间保持存活。

工作进程存活但心跳不健康时会停止报告就绪；本轮守护针对进程退出，不自动杀死存活的疑似卡死进程。守护器自身崩溃、宿主机断电、系统重启和Windows服务注册不在本实现范围内，也没有多机高可用保证。

## 本轮真实进程验收

在独立备份恢复副本、demo模式下运行 `scripts/accept_supervised_recovery.py`，未调用付费模型。

- 实际杀掉已领取任务的冷工作进程，约0.842秒恢复就绪，期间503可见，API/UI PID保持不变，后续区域仓储任务返回10件。
- 原任务约60.175秒后因真实租约自然到期变为interrupted；未自动重放，新键重提成功。
- 继续杀进程，验证三次重启预算和预算耗尽后的全部自有进程关闭。
- 重复启动器拒绝、重新启动后预算重置、正常关闭不重启均通过。
- Windows实际PID/依赖环境、退避、错误会话与PID、状态写入失败、预算耗尽和接口进程退出等回归测试通过；全量333项通过，另有一条既有测试依赖弃用提示。
- 业务库字节和主实例任务未改变，验收子进程全部停止。

上述恢复时间是本机有界样本，不是长期SLA，也不代表真实模型容量。

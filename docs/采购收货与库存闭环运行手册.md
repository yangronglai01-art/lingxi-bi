# 采购收货与库存闭环运行手册

本功能使用自建模拟数据和本地 JSON 批次，不表示已接入小佩真实采购或仓储系统。

## 操作入口

协议 v1 新增 `purchase.created` 和 `purchase.received`。示例需要替换供应商、SKU、仓库为现有主数据，业务ID每次新业务必须唯一。

```json
{
  "version": 1,
  "source": "mock_procurement",
  "batch_id": "purchase-example-001",
  "events": [
    {"event_id":"po-example-001","kind":"purchase.created","purchase_id":"PO-EXAMPLE","supplier_id":"S1","purchase_date":"2026-09-01","items":[{"purchase_item_id":"PI-EXAMPLE","sku_id":"P001-S1","quantity":10,"amount":"1000.00"}]},
    {"event_id":"rc-example-001","kind":"purchase.received","receipt_id":"RC-EXAMPLE","purchase_item_id":"PI-EXAMPLE","warehouse_id":"W1","receipt_date":"2026-09-02","quantity":5}
  ]
}
```

依次执行：

```powershell
.\.venv\Scripts\python.exe scripts/ingest_upstream.py ingest --file <批次JSON路径>
.\.venv\Scripts\python.exe scripts/manage_releases.py validate --generation <候选版本>
.\.venv\Scripts\python.exe scripts/manage_releases.py activate --generation <候选版本> --expected-current <父版本>
```

接入仅生成候选，校验、发布后才供员工问数。既有批次原样重试安全；同一事件ID或批次ID内容改变会拒绝。依赖事件需先出现，例如先创建采购再收货、先入库再发货；不自动为未到达事件垫库存。

## 数据规则

- 采购日期限定为2025-10-01至2026-09-30；收货不早于采购且不晚于观察截止日2026-10-16。
- 数量严格为整数，金额为正数、两位小数字符串；校验供应商、SKU、仓库存在，采购头和明细ID唯一。
- 支持同一采购行分批、跨仓收货；所有仓库累计收货不得超过采购数量。
- 收货与正向库存流水在同一事务中写入，并重算收货日之后已有库存快照、补齐收货日快照。任何事件失败，整批业务修改回滚，错误来源隔离并留审计。
- 逐笔核对新增来源事件、采购/收货行与库存流水；全量门禁同时检查超收、日期、逐日非负库存和库存快照账实一致。
- 期末库存按SKU、仓库分别选范围内最新快照，再按型号汇总；不会因某仓更新更晚而丢掉其他SKU或仓库。
- 区域账号仅查看本区收货、入出库与库存。采购头明细没有地区归属，暂不对区域账号开放，防止通过采购数量泄露其他仓库数据。

## 本轮验收

两笔采购各10件、各分两次收货5件，两区累计入库20件。超收批次包含一个先成功创建的采购及一个失败收货，整个候选事务回滚，正式版本未受影响。重复接入、显式历史回滚后重新接入、区域执行视图均验收通过。

新增24项测试覆盖部分收货、跨仓超收、主数据、日期、数量约束、来源金额篡改、入库支持出库、顺序错误回滚和权限。全量测试281项通过，另有一条既有测试依赖弃用提示。

演练脚本 `scripts/exercise_procurement.py` 会创建新的独立模拟采购并执行发布/历史回滚/重放，会增加模拟业务数据，仅限可信本地操作者使用，不应当作只读检查。

本轮证据：`reports/petkit500_procurement_acceptance.json`；库存真实模型验收：`reports/petkit500_inventory_model_acceptance.json`；恢复证据：`reports/petkit500_restored_source_acceptance.json`；汇总：`reports/petkit500_procurement_rollout_summary.json`。

## 已知范围

这是SKU和仓库级数量库存，尚无序列号入库、质检、拒收、退供、应付或供应商付款。退款不自动触发实物回库。历史种子收货与库存流水分别生成，新增来源收货才具备逐笔入库对账；不能据此声称所有历史采购已经完成实物入库对账。当前仍为单机实例，未验收真实接口、长期负载及高可用。

# 新增订单接入与验收记录

本阶段已完成，数据全部自行模拟，不代表接入小佩真实系统。

## 实施范围

扩展本地 JSON 批次协议 v1，增加 `order.paid`。同一事务写入订单、明细、支付、实物设备及订单设备关系，后续激活、工单和退款可以在同一批次按依赖顺序接入。

客户地区、SKU 型号和支付日有效成本均由主数据推导。拒绝调用方传入地区、金额不平、设备数量不符、重复业务 ID、未知主数据、未来生产日期及超出历史窗口的订单。单批最多新增 1,000 台设备。任一事件失败则整批回滚。

## 本次验收

- 新增 R1、R2 各一笔订单，每单两台设备；各增加一次激活、工单和退款，共 8 个事件。
- 订单从 3,200 增至 3,202；实付增加 400 元，退款增加 20 元，净销售额增加 380 元。
- 500 表发布门禁、来源归档与业务行对账、32 条独立业务口径校验通过。
- 重复批次返回 already_applied；执行层区域视图分别仅显示本区新增订单和工单。
- 新增 12 条测试覆盖金额、主数据推导、重复设备和批次原子回滚。

## 使用与边界

`scripts/ingest_upstream.py` 生成候选，`scripts/manage_releases.py validate --generation <候选>` 校验，然后用 `activate --generation <候选> --expected-current <父版本>` 发布。发布前不会改动当前业务版本。

这是固定历史窗口 2025-10-01 至 2026-09-30 的已支付订单补录，观察截止日 2026-10-16。未实现实时 OMS 连接、履约发货、库存扣减、取消或反向冲销；不能把已支付自动当作已发货。区域隔离为执行连接上的受控视图，非数据库原生 RLS。

# 灵犀面试演示操作手册

## 启动

先在PowerShell进入项目目录。以下启动器会打开浏览器，凭据只在本次本地服务进程中生成，不修改.env密钥，API和页面都只监听127.0.0.1。

```powershell
cd D:\projects\lingxi
# 稳定离线演示 不调用模型
.\.venv\Scripts\python.exe scripts/start_interview.py --mode demo
```

真实模型演示时，先Ctrl+C停止离线服务，再启动：

```powershell
.\.venv\Scripts\python.exe scripts/start_interview.py --mode llm
```

页面自动使用本次临时演示身份，无需粘贴令牌。真实模式会产生模型API费用。默认页面8501、API8000；端口冲突可用 --api-port 18000 --ui-port 18501。Ctrl+C会停止两项子服务。启动失败日志在data/petkit500/launcher_logs。

## 五分钟展示顺序

1. 先说明业务背景：以小佩公开业务为背景自建模拟数据，核心是销售、设备、售后分析，不是真实客户交付。
2. 展示500表目录和40张核心表，打开订单行、设备桥接、工单表，解释一单多设备、一设备多工单。
3. 提问“各型号净销售额”，展开检索依据、指标口径和SQL，解释退款先按订单行汇总。
4. 提问“2026年9月各型号售出30天售后设备率”，展示分子、分母和百分比，解释成熟窗口及设备去重。
5. 提问“各型号期末库存”，解释快照取最新日，不能跨日期累计。
6. 提问“各型号激活率”，展示澄清；说明权限和危险SQL由独立测试覆盖，不把普通失败包装为安全拒绝。

以上问法在demo模式均可演示，激活率缺口径会澄清。真实模型模式还可以用试跑和留出报告中的问法，不保证任意临场问题都正确。

## 一分钟项目介绍

灵犀是一个面向智能宠物硬件业务的智能问数原型。我以小佩公开业务为背景，自建500张模拟表，其中40张核心表形成销售、设备和售后的分析链路。用户中文提问后，系统检索表字段和指标，补全依赖与批准关系，生成结构化计划和SQL，经过只读、权限、枚举及部分指标口径检查后执行，最后展示结果和图表。

实现中最关键的是多粒度关联和业务值对齐：同一设备多条工单必须去重，退款要先按订单行汇总，状态值必须使用数据库里的真实枚举。工程上保留本地回归和真实模型问题记录，让结果能复现、错误能定位。

## 面试追问时的实际口径

元数据当前使用JSON版本快照；检索已验证本机BGE-M3 CPU语义向量与BM25融合，含持久缓存、指标依赖文档与规则补全；启动器自动读取已构建的模型配置。PostgreSQL、pgvector和生产RLS是后续路线，不属于当前已部署组件。

优先讲一个真实失败案例：模型把“已支付”写成paid，查询正常执行却返回空结果。通过冻结问题集发现后，补齐枚举元数据和执行前值域检查，并保留首轮成绩与定向复核记录。

## 演示前检查

确认当前数据已构建、端口未占用、能打开页面。真实模型网络不可用时，明确切换到demo模式；不会静默将规则结果冒充模型输出。正式面试前亲自走一遍三个场景，确认讲解顺序和页面字号适合展示。

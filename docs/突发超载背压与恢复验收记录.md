# 突发超载、幂等与恢复验收记录

日期：2026-10-17。版本：petkit-v1.3-638f0e235a。

## 方法

在本轮新建的备份恢复副本上启动默认守护模式API、UI及单工作进程，保持后台工作进程正常消费，不人为暂停。预热后使用16个HTTP客户端，集中提交64个不同幂等键的全局净销售额问题；本轮突发发起窗口实际耗时1.05秒。

这与上一轮每个客户端等待结果后再提交的闭环不同，本轮先突发提交，再等待接收任务完成，用于实际触发员工待处理配额20。使用demo批准模板和本地BGE，不调用付费模型；不是全局200任务配额的HTTP饱和测试。

原实例任务记录、版本指针、业务仓库及恢复副本业务仓库均通过不变检查；本轮启动的全部子进程已关闭。创建备份会追加备份审计，因此不声称原控制库完全没有写入。

## 回归与限制

队列背压、全局配额、同键并发幂等及并发员工配额的4项既有针对性回归均通过，1项既有Starlette/httpx弃用提示。全局200配额在本轮只由这组回归覆盖，没有进行200任务的实际HTTP压测。

没有修改业务实现，无需把这64次提交加进354项软件测试计数。354是上一轮完整回归结果，本轮另执行4项针对性复核。没有测多实例、长期稳定性、真实模型容量或生产SLA；本轮证明的是当前单机模拟实例遇到单员工突发超载时能按既有配额拒绝、保持幂等，并在排空后恢复查询。

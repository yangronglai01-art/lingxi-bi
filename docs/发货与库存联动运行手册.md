# 发货与库存联动运行手册

所有业务数据和上游批次均为自行模拟，没有接入小佩真实系统。

## 接入

在协议 v1 的 events 中新增以下事件，数量由订单行按 SKU 聚合推导，不接受调用方传入数量或地区。

```json
{"event_id":"ship-event-1","kind":"order.shipped","shipment_id":"SH-EXAMPLE","order_id":"已有且未发货的订单ID","warehouse_id":"订单同地区仓库ID","ship_date":"2026-09-02"}
```

使用 `python scripts/ingest_upstream.py ingest --file <批次JSON路径>` 接入候选；候选接入成功后，依次执行 `scripts/manage_releases.py validate --generation <候选>` 和 `activate --generation <候选> --expected-current <当前版本>`。操作由本机可信运维执行，不开放任意文件上传或 SQL 写入接口。

一个事件在同一事务中写入物流、按 SKU 汇总的负向出库流水，重算发货日及以后已有库存快照，并补齐发货当日快照。候选发生任何错误则整个批次回滚。正式发布前再次校验500表、来源归档、业务行、逐日库存余额和32条业务口径。

库存检查覆盖所有流水日期，防止历史补录导致后续某日透支。库存快照是派生数据，允许在新候选中重算；旧快照目录保持不可变。重复接入按当前版本血缘跳过；显式回滚后重放会重新扣库一次。

## 业务约束与口径

- 只允许全单一次发货，仓库须与订单同地区；不支持拆单、跨区调拨。
- 发货不能早于支付或设备生产、晚于观察截止日，也不能晚于已有激活或售后。已有发货后新增激活、售后也不能回填到发货前。
- 订单的支付状态保持原值，物流表决定是否已发货。退款仅为金额事件，不自动增加实物库存。
- 期末库存按每个 SKU、仓库各自范围内最新快照汇总，避免异步快照更新遗漏其他 SKU；指定月份时只选择该月范围内的快照，不自动带入月前余额。
- 库存可用量为 SKU、仓库级账面余额，没有预占、锁库存、序列号库存或实物盘点。
- 历史种子物流和库存分别生成，本阶段只对新增发货逐笔建立来源与出库对账；不能把该验证描述为历史全量订单已经完成物流库存对账。

## 验收与恢复

`scripts/exercise_fulfillment.py` 为上阶段两笔未发货订单提供一次性联调演练；已经发货后重跑会主动停止，避免制造新物流。原始证据见 `reports/petkit500_fulfillment_acceptance.json`。

本轮新增14条履约及生命周期测试、3条异步库存口径测试。真实模型库存结果见 `reports/petkit500_inventory_model_acceptance.json`，其结果由 Python 对原始快照独立聚合核验。备份和恢复通过 `scripts/backup_simulated.py --drill` 及 `scripts/accept_restored_sources.py` 验收；不覆盖长期负载或多机高可用。

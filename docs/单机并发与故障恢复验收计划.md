# 单机并发与故障恢复验收计划

在独立备份恢复副本执行，不改写主实例的任务。使用demo模式，真实API、工作进程、SQLite、DuckDB及本地Embedding，不调用外部付费模型。

1. 明确队列满为HTTP429及Retry-After，幂等键冲突仍为409；新增配额与并发幂等回归。
2. 五种员工身份同时提交任务，十个HTTP并发；逐任务按身份和独立Python数值计算验证成功或权限拒绝，不将拒绝混入成功率。
3. 同一幂等键并发提交只创建一个任务；暂停工作进程，验证每员工20个待处理任务配额及取消后释放容量。
4. 取消已运行任务，确认迟到计算不会发布结果；第二工作进程被单进程锁拒绝。
5. 在独立子进程故障注入：进入实际worker的ask调用后阻塞，杀进程、正常重启，等待真实60秒租约自然到期。原任务标记interrupted，不自动重放；用户新幂等键重提后成功。
6. 保存提交耗时、排队到完成耗时、吞吐和错误明细，确认所有子进程退出、业务仓库字节及主实例任务不变。

边界：有界单机样本，不是长期稳定性或真实模型并发容量测试。运行取消只约束结果发布，不能保证已开始的外部模型调用停止计费。故障注入阻塞仅在验收子进程内，不添加生产延迟开关。

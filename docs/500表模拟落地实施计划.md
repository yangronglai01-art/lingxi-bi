# 灵犀 500 表模拟落地实施计划

日期：2026-10-16

## 目标与边界

基于小佩公开业务背景建设自有模拟数据，不代表真实企业交付。保留原有6表代码和数据库，新增500表运行配置，默认展示小佩模拟场景。按已确认范围先完成代码、数据构建和操作文档，不运行测试、模型评测或压测，不报告准确率。

## 执行步骤

1. 建立独立模块 src/petkit，定义40张核心表、460张按领域和业务主题区分的扩展表，以及字段、粒度、关系、指标和权限元数据。
2. 实现固定种子的模拟数据生成器。核心数据覆盖商品、订单、支付、退款、设备、激活、绑定、固件、售后及库存等关系。扩展表明确标注为模拟分析表，不把目录规模当作业务全覆盖。
3. 构建独立 data/petkit500/ 数据目录，保存DuckDB、JSON目录、指标、关系、数据摘要。构建先写临时文件，再发布新版本，原6表数据库不修改。
4. 实现本地BM25与字符向量融合检索，支持可选sentence-transformers真实Embedding；返回检索证据、方法、依赖与关系补全，严格控制上下文预算。字符向量模式明确标注为词法近似，不冒充BGE或语义模型。
5. 实现问题澄清、版本绑定、SQL上下文、明确标注的离线模板模式、真实模型模式、有限修复和错误分类。模板仅匹配批准问题，未识别问题返回无法回答，不猜SQL。
6. 使用SQLGlot完成只读AST、函数、表列与作用域检查；授权和检索上下文分别校验；受控DuckDB执行提供超时取消、进程内并发、内存与结果限制。演示权限以可信配置映射主体，不信任客户端自报角色；不声称完整生产RLS。
7. 接入CLI、FastAPI、Streamlit，展示500表目录、检索依据、SQL、口径、状态和结果；历史按主体存储隔离。新增演示凭据配置，生产模式缺失配置时拒绝请求。
8. 编写可复现构建说明、典型问题、参考SQL评测资产和后续验证清单。安装必要轻量依赖，执行数据构建与Python语法检查；不运行问数测试或模型请求。

## 交付与完成标准

- 代码和配置文件落在项目中，500表具有结构化说明，40张核心表形成关联数据。
- 生成实际500张物理表、数据目录与构建摘要；若依赖不可用，明确记录阻塞而不伪称已生成。
- 入口统一切换到新场景，同时保留legacy配置。
- 文档准确区分已实现、本地近似能力、可选组件与未经测试状态。
- SQLite/JSON本地元数据是本轮实现，PostgreSQL/pgvector、正式SSO、原生RLS、高可用和完整500表问数覆盖不包含在首轮交付中。

# 500表模拟落地第二阶段实施计划

日期：2026-10-17。目标是可持续运行的单机模拟业务实例，自建数据，不连接小佩真实系统。

1. 建立持久化控制库：保存模拟员工、部门、令牌摘要、授权版本与操作审计；支持禁用用户与轮换令牌。生产式模拟运行必须认证，禁止默认匿名分析员。
2. 落实地区数据权限：在DuckDB执行连接中安装受限临时视图，原始表只能由执行层引用；区域员工直接查订单行、退款、设备或售后也受地区约束。无法推导区域的表拒绝开放。保留全局分析员以对账。
3. 建立持久化问数任务：API提交、查询、取消，工作进程从控制库领取任务；身份和权限在执行及读取结果时复查，进程退出留下的运行任务可恢复为中断状态。明确单工作进程范围。
4. 形成固定模拟组织及启动方式：全局分析、区域销售、区域售后、受限查看员工；可重复初始化，默认不覆盖已有凭据。新增健康、任务与审计运维入口。
5. 自动化验收：区域汇总与独立原始记录计算对账；直接访问明细不能绕过地区权限；不同用户不可读取任务/历史；禁用及授权变化使旧结果不可取；取消与进程中断恢复；实际HTTP跑通提交到结果。
6. 补齐运行手册及验收报告，区分单机模拟应用级行权限与数据库原生RLS。持久化SQLite与DuckDB适用于本轮单实例，不宣称高可用或分布式部署。

先完成以上闭环，再扩展容器化、多实例队列或真实系统接入。只运行本机服务与自建数据；沿用已有模型配置，不修改原.env密钥。

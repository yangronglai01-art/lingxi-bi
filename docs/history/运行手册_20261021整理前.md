# 灵犀500表模拟业务实例运行手册

日期：2026-10-17。本轮交付的是可持久运行的单机模拟应用，自建数据，未连接小佩真实系统。

## 启动与登录

```powershell
cd D:\projects\lingxi
# 已完成初始化；重复执行不覆盖已有账号授权或令牌
.\.venv\Scripts\python.exe scripts/provision_simulated.py
# 默认使用现有真实模型配置
.\.venv\Scripts\python.exe scripts/start_simulated.py
```

业务工作台：http://127.0.0.1:18501 。API：http://127.0.0.1:18000/docs 。启动器同时管理API、工作台、后台执行器三项服务。Ctrl+C停止它们，持久数据保留。默认仅监听本机，暂未配置内网HTTPS或外网发布。

在本机 `data/petkit500/simulated_credentials.json` 选择员工对应的访问凭据，粘贴到工作台登录框。此文件是本机测试账号的明文凭据，不提交仓库或外传；控制库仅存令牌摘要。原.env模型密钥未修改。模拟实例必须认证，不再使用匿名分析员或每次启动随机身份。

无需模型费用的功能验证可显式运行 `scripts/start_simulated.py --mode demo`，仅支持32个批准问题；真实业务自由问法用默认llm模式。模型服务失败会明确失败，不降级成模板。启动器会读取现有BGE本地配置，模型权重不重复下载。

## 一次实际使用流程

1. 销售员工登录，提交“各型号净销售额”。任务先持久保存，再由后台工作进程领取，结果只含该员工地区的销售与退款。
2. 售后员工登录，提交“各型号售出30天激活率”。以订单所属地区界定售出设备，保留完整成熟队列，输出devices、matched_devices、rate_percent。百分数乘100，分子分母与百分数通过一致性校验。
3. 全局分析员可对账全国数值，查询运维概况；基础查看账号查询销售指标被拒绝。
4. 最近20个当前授权版本任务可在工作台刷新查看。停止、重启应用后，排队任务继续执行；执行中崩溃的任务租约过期后标记interrupted，不自动重复计费。

任务completed表示处理流程结束，必须继续检查result.status是否success。clarification、denied、timeout等均有明确问数状态。取消queued任务立即生效；取消running任务会阻止结果发布，已经发出的外部模型请求不保证立即中断或停止计费。SQL仍有15秒中断预算。

## 权限如何生效

接口身份来自控制库，不接受客户端自报角色或地区。区域身份只允许已明确建模的表；未知区域归属表和460张扩展合成表对区域账号拒绝开放。

- 订单按订单region_id过滤；订单行、退款、支付、物流依赖受限订单集合。
- 设备与激活、设备日、固件升级及工单继承售出设备对应的订单地区；工单状态、维修、换新及反馈继承受限工单集合。
- 仓库及库存按仓库地区；客户、订阅和App会话按客户所属地区；公共产品、渠道、固件等参考主数据按授权共享。

SQL通过AST授权校验后，在每个只读DuckDB连接中创建受限临时视图。直接查询订单行、退款、设备或工单表也不能绕过区域限制，SQL禁止原始库限定名与外部访问。执行前后检查身份版本；禁用或授权变化后不发布旧授权结果。任务和历史结果读取也绑定当前授权版本。

这属于应用执行层强制区域隔离；不是DuckDB数据库原生RLS。持有服务器文件系统权限的运维人员属于本轮信任边界。公司级SSO、列脱敏和更完整组织模型尚未部署。

## 账号维护

在受信任的本机运维终端执行：

```powershell
# 禁用 / 启用；授权版本会变化
.\.venv\Scripts\python.exe scripts/provision_simulated.py --disable regional_sales
.\.venv\Scripts\python.exe scripts/provision_simulated.py --enable regional_sales
# 新建或更改地区授权；空regions表示全局授权，需谨慎配置
.\.venv\Scripts\python.exe scripts/provision_simulated.py --subject sales_r3 --department 区域三部 --role sales --regions R3
# 轮换启用账号的令牌；原令牌立即不再通过后续认证
.\.venv\Scripts\python.exe scripts/provision_simulated.py --rotate
```

禁用会阻止新认证及排队任务执行。授权版本变化后，旧任务与旧历史不会自动恢复可见；应重新提交任务。模拟组织初始化不会把已禁用员工重新启用。令牌轮换跳过禁用账号。该维护接口受操作系统访问权限保护，不是对普通业务用户开放的管理API。

## API与故障处理

- GET /me：当前账号、部门、地区和授权版本。
- POST /jobs：提交问题，可传Idempotency-Key；同一授权版本、同一数据版本的相同键和相同问题只创建一个任务。键重复但问题不同返回冲突。
- GET /jobs、GET /jobs/{id}：当前主体、当前授权版本的任务。跨用户和旧授权版本不可访问。
- POST /jobs/{id}/cancel：取消尚未完成任务。
- GET /ready：快照、身份库、工作进程心跳；异常返回503。
- GET /ops/summary：仅全局分析账号，提供任务状态统计与最近50条持久审计。

模拟业务实例的同步POST /ask返回409，统一使用持久任务。每账号最多20个待处理任务，总队列最多200个；当前只有一个后台工作进程。所有接口使用Authorization: Bearer凭据。

工作进程采用文件锁防止同一数据目录重复启动；每15秒续租，租期60秒。崩溃恢复为interrupted后由用户重新提交。审计不可用时，受管员工结果不会发布。日志位于 `data/petkit500/simulated_logs`；当前未配置系统服务自动拉起或日志轮转。

## 备份与恢复

```powershell
.\.venv\Scripts\python.exe scripts/backup_simulated.py --drill
.\.venv\Scripts\python.exe scripts/accept_restored_instance.py
```

第一条使用SQLite在线备份接口，保存控制库及绑定的不可变500表快照、校验清单和向量缓存，并复制到全新恢复目录验证哈希、SQLite完整性、外键和500表。第二条从该恢复目录实际启动独立应用，验证员工登录、区域任务与原实例隔离。完成后关闭测试服务；现有实例不被覆盖。

本轮恢复目录：`D:\projects\lingxi\data\petkit500\restore_drills\2a049928d44f`。真实恢复应用已通过，但没有自动切换原服务、没有自动灾备，也未测量RTO/RPO。备份含问题和结果，应按业务数据保护；不含明文员工凭据及模型权重。此机恢复验收复用原机保留的测试凭据和本地模型。换机器需重新配置模型及轮换员工令牌。

如需手工运行恢复副本，可使用 `scripts/start_simulated.py --data-dir '恢复目录'`，并配置该副本需要的凭据与模型。新目录初次初始化/轮换凭据时可先设置PETKIT_DATA_DIR为副本目录再运行provision脚本；务必核对目录，避免操作原实例。备份恢复脚本默认不覆盖任何现有目录。

## 验收结论

200项回归通过。真实HTTP分别验证了离线模式与真实模型的多员工流程、跨用户拒绝、区域销售和激活率独立计算、排队与取消状态重启持久化。首次受管模型验收发现0到1小数与百分数输出不统一，原记录保留，增加版本化输出契约与校验后再次验收通过。SQL语义校验仍是有限规则，不是所有SQL业务正确性的证明。

证据：`reports/petkit500_simulated_rollout_summary.json`、`petkit500_simulated_acceptance.json`、`petkit500_simulated_llm_first.json`、`petkit500_simulated_llm_acceptance.json`、`petkit500_backup_drill.json`及`petkit500_tests.xml`。

此前本机1/4/8并发测试属于离线链路，不是当前真实模型队列的容量保证。尚未进行长期负载、多实例、高可用或真实企业系统联调验收。

# 500 表模拟数据与后续验证

## 数据分层

40张核心表包括12张维表和28张事实或桥接表。460张扩展表由10个域、每域23个业务主题、日与月两种粒度构成。每个扩展表都有型号键、期间、计数和量值，名称与描述区分业务主题；量值为独立合成，仅用于检索与长尾实验，不是经过真实业务定义的指标。

核心对象关系：客户→订单→订单行→设备桥接→设备；SKU→型号；退款→订单行；激活→设备；工单→设备；维修、反馈、换新→工单。每个订单可有多行，每行可多设备，每设备可多工单。换新设备用独立X前缀，不重复作为原始售出设备。

库存快照由独立开账库存及出入库流水累计构成。采购收货是单独的演示链路，本轮不声称已经实现采购、销售和库存的全量财务闭环；营销与订阅也是独立的模拟场景。统一版次不等于全业务对账完成。

设备日数据仅采样激活后最多15天；离线率分母为采样设备日，不能当作真实全量在线率。未满30天售出设备不进入30天激活/售后率分母。所有时间范围截止至固定观察日，净销售额的退款按原订单支付月归属。

## 构建与发布

构建新目录、批量建表并写入、完成数据库事务、写入catalog与summary，最后替换current指针。失败构建保留未发布目录供排查，不影响之前发布版本。运行中的问数绑定generation，索引和数据库沿用同一版本，不混用。

不自动清理旧快照，防止删除仍被使用的版本；大型重复构建需人工按保留策略管理空间。

## 模拟异常

型号P003的退款和售后概率被有意提高，固件V2在采样数据中离线概率偏高。它们是生成器注入的模式，用于演示查询，不是对小佩产品或固件质量的判断；不能输出真实品牌质量结论。

## 初始验证清单

1. 检查500张物理表与目录、行数、字段、孤儿键、时间先后和金额边界。
2. 独立核验净销售额、30天激活/售后设备率、离线率和库存参考答案。
3. 比较全量Schema、BM25、词法向量、真实Embedding与关系补全，记录逐题完整召回。
4. 测试模板32题与LLM结构化输出、澄清、无数据、失败修复和超预算。
5. 用CTE、嵌套查询、别名、UNION、函数、表函数、外部访问、OR关联和多语句验证guard边界。
6. 测试角色越权、伪造凭据、历史ID猜测、凭据切换和元数据泄露。
7. 测试查询取消、结果截断、内存边界及多进程并发；确认计时和审计失败策略。
8. 冻结盲测问题，排除模板题泄漏；生产前补充正式身份与执行层行列权限。

## 已知限制

默认字符哈希向量仅是词法近似；指标路由是词匹配；没有学习式reranker；元数据不是PostgreSQL/pgvector；AST不是业务正确性证明；演示角色不是企业SSO/RLS。所有质量、性能和安全能力都需要实际运行验证。后续验证应把错误定位到具体环节，再修改设计和代码。
